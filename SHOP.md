## 1. Контекст проекта

- Проект: кастомная WordPress-тема `nice-hair`.
- Стек: WordPress, WooCommerce, Gutenberg, ACF Pro, Vite, Sass/SCSS, ручная theme-верстка.
- Бизнес-логика по возможности остается внутри темы; отдельный mini-plugin не вводим без отдельного запроса.
- `Shop` остается лендингом и входной точкой в интернет-магазин, а не классическим catalog grid.
- `Home` и `Salon` не трогаем, если это не требуется для shop-части.
- Покупательский личный кабинет не нужен.
- Продажи идут в guest-режиме.
- Текущая архитектура темы и визуальный язык должны сохраняться.

Текущее подтвержденное состояние проекта:
- Для `Shop` уже есть отдельные `header-shop` и `footer-shop`.
- WooCommerce уже интегрирован и частично кастомизирован темой.
- Для `Tools` уже существует отдельный custom single-product шаблон.
- Cart / checkout уже рассматриваются как часть shop-flow и работают без customer account.

## 3. Подтвержденные shop-направления

### 3.1. Keratin

Общая логика:
- у `Keratin` нет фильтров;
- путь клиента строится через вход в раздел `Keratin`, затем выбор подтипа;
- подтипы:
  - `Pigmented keratin`
  - `Italian gel keratin`
- после выбора подтипа клиент попадает в список цветовых позиций;
- при выборе цвета открывается карточка конкретного товара;
- внутри карточки цвет уже предопределен и не выбирается повторно;
- в карточке клиент выбирает только вес;
- цена должна меняться в зависимости от веса;
- покупка идет в штуках, где штука = упаковка выбранного веса.

Состав каталога:
- `Pigmented keratin`:
  - Brown
  - Dark brown
  - Black
- `Italian gel keratin`:
  - Transparent
  - Perl
  - Middle
  - Honey
  - Dark
  - Brown
  - Blond

Требование к расширяемости:
- в `Pigmented keratin` и `Italian gel keratin` должна быть возможность добавлять новые цветовые позиции без пересборки архитектуры каталога.

### 3.2. Tools

Подтвержденное поведение:

- sale / regular price должны поддерживаться штатно;

### 3.4. Exclusive hair

Общая логика:
- раздел открывает каталог с фильтрами;
- в каталоге нужны `Best seller` и sale badge;
- в карточке товара клиент выбирает, что именно сделать из конкретного среза волос, либо покупает волосы как `Bulk`;
- `Video` ведет на YouTube-обзор конкретного среза;
- `How to use` нужен в карточке товара, но остается на уровне самого товара, без shared term-логики.

Фильтры:
- `Texture`
  - Amazing curly
  - Silky wavy
  - Soft straight
- `Color`
  - Dark
  - Middle
  - Light

Критически важное поведение:
- каждая позиция `Exclusive hair` существует в единственном экземпляре;
- после покупки такая позиция должна становиться `Sold` / `Out of stock`;
- клиент не должен иметь возможность купить одну и ту же позицию повторно;
- в карточке нельзя выбирать длину, цвет, вес: они уже зафиксированы у конкретного товара;
- клиент выбирает только тип изделия, в которое превращаются выбранные волосы.

### 3.5. Custom hair

Карточка товара:
- первое фото соответствует выбранному изделию;
- при выборе цвета должен меняться вид / изображение изделия;
- нужно добавить выбор веса;
- стартовый вес: `30 гр`;
- шаг: `10 гр`;
- итоговая стоимость рассчитывается по формуле из Excel;
- `How to use` нужен;
- `Video` ведет на YouTube-обзор выбранного изделия.

## 4.2. Custom hair: формула расчета

Источник: лист `расчет кастом и эксклюзив`.

База 1. Цена волос за 1 грамм по `quality + length`:

| Quality | Length | Price / 1 gr |
| --- | --- | --- |
| Lux | 40 | 2.25 |
| Lux | 50 | 2.45 |
| Lux | 60 | 2.65 |
| Lux | 70 | 3.05 |
| Lux | 80 | 3.45 |
| Premium | 40 | 2.45 |
| Premium | 50 | 3.25 |
| Premium | 60 | 3.55 |
| Premium | 70 | 3.85 |
| Premium | 80 | 4.25 |

База 2. Цена изделия за 1 грамм:

| Изделие | Price / 1 gr |
| --- | --- |
| Biotape | 0.66 |
| Bulk | 0 |
| Double layer hand-tied weft with clip-in | 1.3 |
| Flat keratin bonds | 0.4 |
| Flat weft | 1.02 |
| Genius weft | 1.02 |
| Hand-tied weft | 1.2 |
| I-tip (round tips) | 0.52 |
| Invisible tapes | 0.8 |
| Machine weft clip-in | 1 |
| Machine weft | 0.86 |
| Mini tapes "butterflies" | 0.66 |
| Nano bonds with metal round tip | 0.72 |
| Nano bonds with metal straight tip | 0.72 |
| Nano bonds with plastic tip | 0.62 |
| Nano bonds with thread tip | 0.72 |
| Ponytail with ribbon | 1 |
| Usual tapes | 0.66 |

Формула:
- `base_hair_price = hair_price_per_gram * selected_weight`
- `product_form_surcharge = item_type_price_per_gram * selected_weight`
- `total_price = base_hair_price + product_form_surcharge`

Пример из таблицы:
- клиент выбрал `Genius weft` из волос `Premium`, длина `60`, вес `60 gr`;
- цена волос: `3.55 * 60 = 213`
- доплата за изделие: `1.02 * 60 = 61.2`
- итог: `274.2`

Ограничения:
- минимальный вес заказа: `30 gr`
- шаг изменения веса: `10 gr`

## 4.3. Exclusive hair: текущая предполагаемая логика

Источник: лист `расчет кастом и эксклюзив`.

Предполагаемая модель:
- у каждого уникального среза волос есть собственная базовая цена за весь лот;
- у конкретной позиции уже фиксированы:
  - длина
  - вес
  - цвет
  - texture
- клиент выбирает только тип изделия;
- доплата за тип изделия считается по той же таблице `цена за 1 гр`, что и для `Custom hair`;
- итоговая цена = `цена уникального лота + доплата за выбранный тип изделия`.

Пример базы:

| Волосы | Length | Weight | Base price |
| --- | --- | --- | --- |
| Exclusive | 63 | 97 | 4000 |

Пока не зафиксировано окончательно:
- останется ли у `Exclusive hair` доплата за изделие весовой;
- или для этой категории будет введена отдельная фиксированная цена за тип изделия.

## 5. Модель данных и админская модель

## 5.1. Общий принцип

- Источником истины должны быть structured data, а не парсинг названия товара.
- Название товара может содержать человекочитаемую строку для фронтенда.
- Фильтрация, расчет и служебная логика должны опираться на taxonomies / attributes / meta / ACF fields.

## 5.2. Что должно храниться структурно

Через Woo attributes / taxonomies:
- тип изделия / `Hair extensions type`
- `Hair Quality`
- `Color`
- `Texture`
- длина
- вес

Через product meta / ACF:
- `Video URL`
- флаг `Best seller`
- данные для `How to use`
- unique item flag
- флаг / логика `Sold`
- данные для динамического расчета цены
- изображения по цветам для `Custom hair`
- служебные значения для pricing rules

Штатные поля WooCommerce:
- regular price
- sale price
- stock quantity
- stock status
- `sold individually`

Публикация / скрытие позиций:
- базово использовать стандартный publish status WooCommerce / WordPress;
- отдельный custom toggle нужен только если стандартного `Draft / Published` окажется недостаточно.

## 5.3. Рекомендованная модель по категориям

### Keratin

Рекомендуемая модель:
- один товар = один цвет;
- вес реализуется через вариации или через контролируемую структуру, где вес является единственным выбираемым параметром;
- `Pigmented keratin` и `Italian gel keratin` удобнее держать как отдельные подкатегории / логические группы;
- `Transparent keratin` не должен наследовать общую цену Italian по ошибке, у него своя тарифная сетка.

### Tools

Рекомендуемая модель:
- обычные simple products;
- количество покупается в штуках;
- `Video URL` хранится на уровне товара;
- sale/regular price использовать штатно.

### Ready to install

Рекомендуемая модель:
- simple products с filterable attributes;
- количество покупки ограничить одной единицей, если товар действительно уникален;
- stock quantity = `1`, `sold individually = yes`, auto `out of stock` после покупки;
- `How to use` лучше привязывать к типу изделия, а не дублировать вручную в каждой цветовой карточке.

### Exclusive hair

Рекомендуемая модель:
- simple product с уникальной базовой ценой и stock quantity = `1`;
- параметры лота фиксированы в самом товаре;
- выбор типа изделия в карточке не должен превращать товар в отдельный складской остаток;
- `How to use` хранится на уровне товара и открывается из single product drawer;
- после покупки товар должен автоматически перейти в недоступный статус.

### Custom hair

Рекомендуемая модель:
- отдельные позиции каталога соответствуют видам изделий;
- внутри карточки клиент выбирает:
  - цвет
  - вес
  - тип / форму изделия
- цена считается динамически на основе служебных таблиц;
- изображения должны поддерживать смену вида по выбранному цвету.

## 7. Акции и скидки

Источник: лист `акции`.

Заказчик хочет управляемую promo-логику с возможностью включать / выключать сценарии и менять контент.

Запрошенные promo-сценарии:
- бесплатная доставка от суммы заказа;
- скидка `%` на чек;
- бесплатный подарок к заказу;
- popup-коммуникация об акции;
- возможность применения акционной логики на этапе расчета / checkout flow.

На текущем этапе это требования, а не утвержденная техническая реализация.

Важно:
- нельзя молча зашивать одну promo-механику как единственную;
- нужно предусмотреть, что разные акции могут потребовать разный механизм применения:
  - cart fee / cart discount;
  - free shipping rule;
  - gift item logic;
  - popup-only communication without automatic discount.

## 8. Риски и открытые вопросы

### 8.1. Несостыковка в таблице цен

На листе `расчет кастом и эксклюзив` есть несоответствие:
- `Premium / 40 cm` указан как `2.45` за 1 грамм;
- при этом `за 100 гр` указано `275`.

Если считать линейно, при цене `2.45 / gr` значение за `100 gr` должно быть `245`, а не `275`.

Это нужно уточнить с заказчиком до реализации pricing engine.

### 8.2. Exclusive hair: не до конца зафиксирована модель доплаты

Пока не подтверждено:
- доплата за выбранный тип изделия считается по формуле `цена за 1 гр * вес`;
- или для `Exclusive hair` будет фиксированная цена по типу изделия.

### 8.3. Title-based filtering технически ненадежен

Заказчик в исходном описании привязывает фильтр к ключевым словам в title.

Для реализации это риск:
- названия могут меняться редактором;
- одно и то же значение можно записать по-разному;
- title не должен использоваться как служебная база для фильтрации и расчета.

Вывод:
- title остается только фронтенд-представлением;
- фильтры и pricing должны опираться на структурные данные.

### 8.4. Sold / hidden behavior после покупки

Не до конца согласовано, что именно должен видеть следующий пользователь после покупки уникального товара:
- карточка остается в каталоге со статусом `Sold`;
- или карточка автоматически скрывается из каталога;
- или остается видимой только в архиве / истории.

Для `Exclusive hair` в описании явно фигурирует слово `sold`, поэтому визуальный sold-state желательно сохранить, но это нужно подтвердить.

### 8.5. Promo rules пока не зафиксированы до уровня комбинаций

Пока не подтверждено:
- могут ли акции сочетаться между собой;
- может ли одновременно работать скидка на чек и подарок;
- popup является только сообщением или триггером применения скидки;
- акции задаются глобально или помесячно / по датам / по категориям.

## 10. Внутренние интерфейсы, на которые опираемся дальше

В этом документе не вносятся runtime-изменения, но дальнейшая реализация должна опираться на следующие внутренние договоренности:
- shop-flow остается `Shop landing -> category page / catalog -> single product -> cart -> guest checkout`;
- structured product data важнее названия товара;
- media и служебные состояния товара управляются на уровне product meta / ACF / Woo fields;
- `Exclusive hair` и `Ready to install` поддерживают unique-stock поведение;
- sale price и regular price по возможности реализуются штатно средствами WooCommerce;
- текущая архитектура темы сохраняется, без перехода на новый plugin-driven слой.

## 12. Вывод для команды

Главная сложность shop-части проекта находится не в верстке, а в правильной продуктовой модели:
- разные категории требуют разной логики товара;
- часть каталога живет на обычных Woo-ценах;
- часть требует формулы;
- часть требует unique-stock поведения;
- promo-логика пока не зафиксирована окончательно.

Поэтому следующая реализация должна начинаться с data model и pricing rules, а не с шаблонов интерфейса.
